## Objective
- Business outcome: Ship the **orchestrator service** — the persistent Python `Deployment` that runs in the factory namespace on the SKE control-plane node pool and drives every autonomous factory execution. The orchestrator is one of exactly three C7 emitters (per `docs/blueprint/architecture/decisions/ADR-issue-337-c7-emission-mechanism.md` and `ADR-issue-347-human-sdd-c7-symmetry.md`), owns phase-boundary C7 event emission, subscribes to the #336 webhook handler's trigger queue, invokes the OpenHands Agent Server (#335) per the SDD-step × expert dispatch matrix in `docs/blueprint/autonomous-factory/design-contracts.md` § Contract C3, validates skill outputs against the YAML jsonschema authored in each `SKILL.md` `## Required Output Schema` block (#360), and packages itself as a reusable Helm chart under `scripts/templates/infra/orchestrator/` per Contract C8.
- Success metric: A `phase: intake` C7 event for a factory work-item is emitted by the orchestrator (`emitter: orchestrator`) to the durable bus with all eleven sealed minimum fields populated and a deterministic `event_id = sha256(ticket_id|phase|rerun_round|emitter)`, validated against the C7 schema in `docs/blueprint/autonomous-factory/design-contracts.md` § Contract C7; the same event carries the additive extension fields `outcome_details.expert_verdicts[]`, `outcome_details.routing_keys`, `outcome_details.token_usage`, and `outcome_details.merger_overhead` per ADR-issue-364 § 9 and ADR-issue-368.

- FR-003 The orchestrator MUST implement the three convergence modes defined in `docs/blueprint/architecture/decisions/ADR-issue-364-expert-persona-model.md` § 4 / § 5: (a) `parallel-then-merge` (default; steps 01/02/04/06/07): N panel members run independently, the merger applies precedence `block > revise > pass`, finding-text deduplication is naive string-equality at v1 (embedding-based dedup is explicitly deferred per ADR-issue-364 § 11 and the AGENTS.backlog after-issue-368 entry); (b) `sequential-lens` (step05 only): each expert sees the prior expert's deltas in the documented application order from § C3 row 5; (c) `structured-disagreement` (step08 only): experts respond to each other's verdicts before the orchestrator merges. C7 emission is owned by child `#361.2`.

Extension-field population is owned by child `#361.2`.

### Non-Functional Requirements (Normative)
- NFR-SEC-001 The orchestrator pod MUST run as a non-root user with a read-only root filesystem; the Helm chart `securityContext` MUST set `runAsNonRoot: true`, `runAsUser: 65532` (or a comparable distroless UID), `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, and `capabilities.drop: ["ALL"]`. Credentials MUST be sourced only via ESO-mounted volumes (no environment-variable secret injection from K8s `Secret` env refs). The orchestrator container image MUST be distroless or equivalent; busybox/alpine shells MUST NOT be present in the runtime image.
- NFR-OBS-001 The orchestrator MUST log structured JSON to stdout for every dispatch decision, every skill invocation, every schema-validation outcome, and every C7 emission; log fields MUST include `ticket_id`, `phase`, `rerun_round`, `event_id`, `decision_summary`. The orchestrator MUST expose a Prometheus `/metrics` endpoint with counters for: dispatched skills, schema validation failures, C7 emissions by phase, panel convergence outcomes by mode. The orchestrator MUST emit the additive extension field `outcome_details.token_usage` on every panel-dispatched C7 event so per-ticket cost is queryable from the C7 stream alone (per ADR-issue-368).
- NFR-REL-001 The orchestrator MUST tolerate at-least-once delivery of `#336` trigger messages: duplicate dispatches for the same `(ticket_id, phase, rerun_round)` tuple MUST collapse to a single C7 event at the bus via the deterministic `event_id` rule. The orchestrator MUST be restart-safe: on pod restart, in-flight panel invocations MUST resume from the durable bus event log (NOT from in-memory state); the per-ticket token accumulator MUST be rebuilt from the bus on restart. Helm rolling-update MUST set `maxUnavailable: 0` and `maxSurge: 1` so the orchestrator is never offline during upgrades. Rollback is `helm rollback orchestrator <previous-revision>`.
- NFR-OPS-001 The Helm chart MUST ship a Kubernetes `Deployment` with `replicas: 1` (single-writer to the per-ticket token accumulator; horizontal scaling is out of scope for v1). Pod liveness MUST be a TCP probe on the Prometheus `/metrics` port; readiness MUST be a synthetic AMQP connection check against the durable bus. The runbook updates MUST cite: (a) how to drain the trigger queue, (b) how to read C7 events from the durable bus, (c) how to look up the most recent `phase: implement` event for reviewer-rotation debugging.
- NFR-A11Y-001 N/A — the orchestrator is a headless Python `Deployment` with no UI surface. Operator observability is via Grafana dashboards authored downstream by `#350`; that work item carries the WCAG 2.1 AA scope for the dashboard surface.
