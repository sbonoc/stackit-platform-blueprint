## Objective
- Business outcome: Ship the **pure-Python core of the orchestrator** — the four importable domain/application-layer components (dispatch matrix loader, convergence engine, schema validator, predicate-registry mechanism) that every other orchestrator child (#361.2, #361.3, #361.4) depends on. ## Normative Requirements

### Functional Requirements (Normative)

- FR-001 The dispatch matrix loader MUST read `docs/blueprint/autonomous-factory/design-contracts.md` § Contract C3 at call time and parse it into a typed in-memory mapping `step → MatrixRow` where `MatrixRow` is a Pydantic v2 model carrying EXACTLY these fields conforming to the `DispatchTableRow` JSON Schema in `docs/blueprint/architecture/decisions/ADR-issue-364-expert-persona-model.md` § 4.1: `step: Literal["step01"..."step08"]`, `skill: str`, `expert_panel: list[str]`, `convergence_mode: Literal["parallel-then-merge","sequential-lens","structured-disagreement"]`, `model_per_expert: dict[str, str]` (keys are expert_slug values, values are LiteLLM routing keys per ADR-364 § 4.3 baseline + per-step overrides), `lead_voice: str | None`, `predicate: str | None`. The loader MUST validate at parse time that: (a) every `skill` value in the matrix resolves to a directory under `.agents/skills/`; (b) every `expert_slug` value in `expert_panel[]` satisfies EXACTLY ONE OF — presence in the sealed `expert_slug_blueprint` enum from design-contracts § C7 F-12, OR presence in the consumer-overlay `expert_slug_extension` allowlist supplied by the caller as a `frozenset[str]` parameter (empty frozenset is the default; callers that have no consumer overlay MUST pass the empty frozenset, not omit the parameter; the caller is responsible for reading `blueprint/contract.yaml` § `factory_contract.expert_panel_extensions[]` and passing the resulting set — the loader performs no contract.yaml I/O); (c) every `predicate` value that is not the literal string `"none"` resolves to a registered name in the `PredicateRegistry` supplied by the caller; (d) every `expert_slug` appearing in `expert_panel[]` MUST appear as a key in `model_per_expert` so #361.2 can populate `outcome_details.routing_keys[]` (per the parent spec routing-key emission requirement) without re-parsing C3 — unresolved or missing routing-key assignments MUST raise `DispatchMatrixError`. The loader MUST raise `DispatchMatrixError` and MUST NOT return a partial result if any validation check fails. The returned mapping MUST cover the 8 SDD steps `step01..step08`; the step-set MUST be derived by parsing the matrix rows, NOT asserted as a literal integer constant.
- FR-002 The convergence engine MUST implement the three convergence modes defined in `docs/blueprint/architecture/decisions/ADR-issue-364-expert-persona-model.md` § 5: (a) `parallel-then-merge` — accept a list of `ExpertVerdict` objects; before any other step, annotate each finding with its source `expert_slug` extracted from the verdict envelope per ADR-issue-364 § 5.1 step 2 (incoming findings from § 6 schema do NOT carry `expert_slug`; the merger MUST add it from the verdict's `expert_slug_blueprint` or `expert_slug_extension` field, preserving provenance through dedup); apply precedence `block > revise > pass` to derive aggregate verdict; apply naive string-equality deduplication on `(category, summary)` tuples per § 5.1 step 3 (kept finding is the one whose source `expert_slug` sorts lowest lexicographically; dropped findings' `expert_slug` values are appended to the kept finding's `co_reporters: list[str]`); apply severity escalation per § 5.1 step 4 (kept finding's `severity` MUST be the maximum across all collapsed copies, applying the ordering `critical > high > medium > low > info`); apply stable ordering per § 5.1 step 5 (the returned `findings` list MUST be sorted by `(severity descending, category ascending, expert_slug ascending)` so audit consumers see deterministic output for the same input panel); return `MergeResult(aggregate_verdict, findings, findings_before_dedup, findings_after_dedup, severity_escalation_events)` where `findings: list[Finding]` is the deduped + escalated + sorted findings payload (this list — not just the counts — is what #361.2 emits as the workspace artifact referenced by C7 `evidence_uri`), and `severity_escalation_events: int` counts the number of findings whose `severity` was escalated during the dedup step. (b) `sequential-lens` — accept an ordered list of expert invocation callables and an initial `LensDelta` context representing the cumulative prior findings (read-only to each callable per ADR-issue-364 § 5 Pattern 2 — "The draft itself is not mutated between rounds"; each callable returns a NEW `LensDelta` carrying the prior delta plus its own additions, never mutating the input), invoke each callable in the declared order passing the prior callable's returned `LensDelta` as additional read-only context alongside the original skill draft, and return the final `LensDelta`. (c) `structured-disagreement` — accept (i) a list of `ExpertVerdict` objects and (ii) a `MergeResult` produced by `parallel_then_merge` on the same verdict set, detect cross-lens contradictions per ADR-issue-364 § 5.2 step 1 (any two `block` verdicts whose findings survive dedup on the same `category` are non-identical by construction and MUST be treated as conflicting — NO LLM classification is permitted; dedup survival on shared category is the entire detection criterion), and return `StructuredDisagreementResult(verdicts: list[ExpertVerdict], conflict_pairs: list[ConflictPair], severity_escalation_events: int)` where `ConflictPair` is the Pydantic model `{expert_a: str, expert_b: str, category: str}` naming the two colliding experts and the shared category, and `severity_escalation_events` counts only the conflict-induced escalation events (distinct from the dedup-induced count in `MergeResult`). The convergence engine MUST perform zero I/O.
- FR-003 The schema validator MUST accept a raw skill-output payload (dict) and a skill basename string, locate the skill's `SKILL.md` at `.agents/skills/<skill-basename>/SKILL.md`, extract the YAML content from the `## Required Output Schema` fenced block (`` ```yaml jsonschema ``), compile it as a JSON Schema draft-07 document, and validate the payload against it using `jsonschema`. The validator operates on two distinct failure paths: (a) **parse/compile failure** (missing fenced block, malformed YAML, invalid JSON Schema) — MUST raise `SchemaValidationError(kind="schema-block-missing"|"schema-compile-error", detail=<error message>, context={"skill": <skill-basename>})`; (b) **payload validation failure** (payload does not satisfy the compiled JSON Schema) — MUST return `ValidationFailure(skill=<skill-basename>, evidence_ref=<opaque pointer string>, field_path=<JSON pointer string>, error_message=<raw validator error message>)`. On validation success the validator MUST return `ValidationSuccess(skill=<skill-basename>)`. The validator MUST perform zero I/O beyond the single `SKILL.md` read at validation time; it MUST NOT write to any stream, emit any event, or call any external service. The caller is responsible for converting a `ValidationFailure` return value into a C7 `outcome: rejected` event (scoped to #361.2).
- FR-004 The predicate registry MUST provide a typed `PredicateRegistry` with `register(name: str, fn: Callable[[WorkItemContext], bool]) -> None` and `evaluate(name: str, ctx: WorkItemContext) -> bool` methods. `WorkItemContext` MUST carry at minimum `changed_paths: list[str]` and `has_user_facing_flow: bool`. The registry MUST ship two built-in fixture predicates registered at construction time: `"always_true"` (returns `True` for all contexts) and `"always_false"` (returns `False` for all contexts). `evaluate` MUST raise `PredicateRegistryError` when `name` is not registered. `MatrixRow.predicate` MUST be typed as `str | None` in Pydantic v2; the literal string `"none"` MUST be coerced to Python `None` by a Pydantic field validator at parse time; any non-`"none"` string MUST be treated as a registry name and MUST be validated against the supplied `PredicateRegistry` at matrix-load time (FR-001 clause (c)) — validation MUST NOT be deferred to dispatch time.

### Non-Functional Requirements (Normative)

- NFR-SEC-001 The module MUST NOT access credentials, environment variables with secret semantics, or any external network service. File reads are restricted to EXACTLY TWO categories: (1) `docs/blueprint/autonomous-factory/design-contracts.md` for the dispatch matrix, (2) `.agents/skills/*/SKILL.md` files for schema extraction. No other file path categories are permitted from within the module. Any caller wishing to override paths MUST supply them as constructor parameters — the module MUST NOT read from process environment to determine file paths.
- NFR-OBS-001 The module MUST expose structured exception types (`DispatchMatrixError`, `SchemaValidationError`, `PredicateRegistryError`, `ConvergenceError`) each carrying at minimum a `detail: str` field and a `context: dict` field sufficient for the caller (#361.2) to emit a structured log line per parent NFR-OBS-001. The module MUST NOT write to stdout, stderr, or any log sink — all observable signals are surfaced exclusively via exceptions and return types. This constraint makes the module trivially unit-testable without output capture and ensures the caller owns all observability decisions.
- NFR-REL-001 The dispatch matrix loader MUST validate the complete matrix before returning any result — partial matrix loads are forbidden and MUST be rejected with `DispatchMatrixError`. The schema validator MUST be idempotent: invoking it twice on the same `(payload, skill)` pair MUST return the same result. The predicate registry MUST be immutable after the first `evaluate` call is made; calling `register` after `evaluate` MUST raise `PredicateRegistryError` with a frozen-registry message.
- NFR-OPS-001 `DispatchMatrixError` MUST include the failing row's `step` identifier and the failing value (skill basename or expert slug) so the caller can produce a diagnostic that routes to operator runbook action. `SchemaValidationError` MUST include the failing `field_path` (JSON pointer string) and `raw_error` (validator error message string). `PredicateRegistryError` MUST include the unresolved `predicate_name` and the list of currently registered names.
- NFR-A11Y-001 N/A — this module is a headless pure-Python library with no UI surface. Operator-facing observability is delegated to the caller (#361.2 and #361.3) and downstream Grafana dashboards authored by #350.

## Normative Option Decision
- Option A: Dict-based in-process `PredicateRegistry` — predicates registered by name string as callables against a typed `WorkItemContext`; registry validated at matrix-load time via FR-001 clause (c).
- Option B: `importlib.metadata` entry-point registry — consumer predicates registered as Python package entry points; lookup at matrix-load time queries the installed package's entry-point group.
- Selected option: OPTION_A
- Rationale: The predicate registry in this child ships only fixture predicates (`always_true`, `always_false`); the first real predicate (`ui-fidelity-or-a11y`) ships in #361.5 and can be registered programmatically using the same `register` API. Entry-point registration adds dependency on package distribution machinery that is premature at v1 scale and introduces a test-isolation problem (installed entry points are global state). Option A is extensible without API change: #361.5 calls `registry.register("ui-fidelity-or-a11y", fn)` before passing the registry to the loader.

## Data Models (Normative — Public API surface)

All Pydantic models below MUST use Pydantic v2 (`from pydantic import BaseModel`, NOT `from pydantic.v1`). Every model MUST set `model_config = ConfigDict(extra="forbid")` UNLESS explicitly noted otherwise. Field types use Python 3.13 typing syntax. These models are this module's public API — sibling children (#361.2, #361.3, #361.5) import and construct them; the schemas below are the locked contract.

- **`MatrixRow`** (loader output row): `step: Literal["step01","step02","step03","step04","step05","step06","step07","step08"]`, `skill: str`, `expert_panel: list[str]`, `convergence_mode: Literal["parallel-then-merge","sequential-lens","structured-disagreement"]`, `model_per_expert: dict[str, str]`, `lead_voice: str | None`, `predicate: str | None` (the literal string `"none"` from the matrix MUST coerce to Python `None` via a field validator at parse time).

- **`Finding`** (per-finding payload): `category: str`, `summary: str`, `evidence_ref: str | None = None`, `severity: Literal["info","low","medium","high","critical"]`, `expert_slug: str | None = None` (populated by the merger from the verdict envelope during `parallel_then_merge` per ADR-issue-364 § 5.1 step 2; absent on findings as returned directly by experts per § 6 schema), `co_reporters: list[str] = Field(default_factory=list)` (populated by the merger during dedup per § 5.1 step 3; carries the expert_slug values of dropped duplicate findings).

- **`ExpertVerdict`** (per-expert dispatched-output envelope): conforms to ADR-issue-364 § 6 JSON Schema. Exactly one of `expert_slug_blueprint: str | None` or `expert_slug_extension: str | None` MUST be populated per row (enforced via Pydantic v2 model validator). `verdict: Literal["pass","revise","block"]`. `findings: list[Finding]`. When the expert has no concern, `findings` MUST be `[]` and `verdict` MUST be `"pass"` (the empty-findings sentinel from ADR-364 § 6 line 360).

- **`MergeResult`** (output of `parallel_then_merge`): `aggregate_verdict: Literal["pass","revise","block"]`, `findings: list[Finding]` (deduped + escalated + stably sorted per § 5.1 steps 3–5), `findings_before_dedup: int` (≥ 0), `findings_after_dedup: int` (≥ 0), `severity_escalation_events: int` (≥ 0; count of findings whose severity was escalated during dedup per § 5.1 step 4). Invariant: `findings_before_dedup >= findings_after_dedup` and `len(findings) == findings_after_dedup`.

- **`LensDelta`** (sequential-lens accumulator): `prior_findings: list[Finding]` (the cumulative read-only findings observed from all prior experts in the sequence — each callable MUST construct a NEW `LensDelta` rather than mutating its input; the original skill draft is unchanged across rounds per ADR-364 § 5 Pattern 2).

- **`ConflictPair`** (structured-disagreement conflict row): `expert_a: str` (the lexicographically-lower expert_slug), `expert_b: str` (the higher), `category: str` (the shared finding `category` on which the two `block` verdicts collided).

- **`StructuredDisagreementResult`** (output of `structured_disagreement`): `verdicts: list[ExpertVerdict]` (the original verdict set passed in), `conflict_pairs: list[ConflictPair]`, `severity_escalation_events: int` (≥ 0; conflict-induced escalations only — distinct from `MergeResult.severity_escalation_events` which counts dedup-induced escalations).

- **`WorkItemContext`** (predicate evaluation context): `changed_paths: list[str]`, `has_user_facing_flow: bool`. The model sets `model_config = ConfigDict(extra="allow")` so future predicates shipped by downstream children (e.g., #361.5's `ui-fidelity-or-a11y`) can extend the context with additional optional fields without amending this child's exported schema.

- **`ValidationSuccess`** / **`ValidationFailure`**: see FR-003 above for fields.

- **`SchemaValidationError`** / **`DispatchMatrixError`** / **`PredicateRegistryError`** / **`ConvergenceError`**: each carries `detail: str` and `context: dict` per NFR-OBS-001 + NFR-OPS-001. `SchemaValidationError` additionally carries `kind: Literal["schema-block-missing","schema-compile-error"]`.

## Normative Acceptance Criteria

- AC-001 [Dispatch matrix loader reads § C3, rejects unknown skills and experts at load time, accepts consumer-overlay extension slugs, and populates model_per_expert] — verified by T-101, which MUST assert: (a) `DispatchMatrixLoader.load(design_contracts_path, skills_dir, extension_allowlist=frozenset(), registry=registry)` raises `DispatchMatrixError` when invoked against a fixture `design-contracts.md` containing a row with a fabricated skill basename absent from the fixture `.agents/skills/` directory; (b) the loader raises `DispatchMatrixError` when invoked against a fixture containing a fabricated `expert_slug_blueprint` value absent from the sealed baseline enum AND also absent from the `extension_allowlist` (fixture: empty frozenset); (c) the loader accepts an expert slug that appears in the `extension_allowlist` even when it is absent from `expert_slug_blueprint`, returning a valid dispatch table without raising; (d) the loader returns a typed mapping whose key-set equals EXACTLY `{"step01","step02","step03","step04","step05","step06","step07","step08"}` when invoked against the canonical `docs/blueprint/autonomous-factory/design-contracts.md` § C3, with the step-set derived by parsing the matrix rows (the assertion MUST NOT use `len(result) == 8` — it MUST assert `result.keys() == expected_steps` where `expected_steps` is constructed from the parsed row keys); (e) for every row in the returned mapping where `expert_panel` is non-empty, each `expert_slug` in `expert_panel` MUST appear as a key in `model_per_expert` and the corresponding value MUST be a non-empty string matching the LiteLLM routing-key format `^[a-z][a-z0-9-]*/[a-z0-9-]+$` (asserted via regex on at least one fixture row carrying multiple experts); (f) the loader raises `DispatchMatrixError` against a fixture row whose `expert_panel` contains an expert_slug absent from `model_per_expert` (missing routing-key assignment, distinct from invalid slug).
- AC-002 [Three convergence modes produce the documented merger outputs] — verified by T-102, which MUST assert: (a) `ConvergenceEngine.parallel_then_merge(verdicts=[pass_verdict, revise_verdict, block_verdict, pass_verdict])` returns a `MergeResult` with `aggregate_verdict == "block"`, `findings_before_dedup == 4`, `findings_after_dedup` equal to the post-dedup count, and `severity_escalation_events` equal to a specific integer asserted against a fixture that contains at least one duplicate finding with different severities (so the non-zero case is covered); AND `result.findings` is a `list[Finding]` of length `findings_after_dedup`; AND every Finding in `result.findings` has `expert_slug` populated (provenance preserved from the source verdict envelope per ADR-364 § 5.1 step 2); AND any Finding that absorbed a duplicate has `co_reporters` containing the dropped verdict's expert_slug (asserted against a fixture where verdicts from `expert_a` and `expert_b` produce identical `(category, summary)` findings — the kept finding's `expert_slug` is the lower lex sort and `co_reporters == [<higher slug>]`); AND `result.findings` is sorted by `(severity descending, category ascending, expert_slug ascending)` per § 5.1 step 5 (asserted by constructing fixture verdicts whose unsorted natural order differs from the spec sort order, then comparing the actual returned list against the expected sorted list element-by-element). (b) `ConvergenceEngine.sequential_lens(experts=[e1, e2, e3, e4, e5], initial_context=fixture_lens_delta)` invokes each callable in order and passes each callable's returned `LensDelta` as read-only additional context to the next callable — asserted by a spy that records invocation order AND confirms callable[2] received the `LensDelta` returned by callable[1] (NOT the original `initial_context`); AND asserts that the `initial_context` object is unchanged after the full sequence runs (no callable mutated the shared input). (c) `ConvergenceEngine.structured_disagreement(verdicts=[block_verdict_cat_A_from_expert_a, block_verdict_cat_A_from_expert_b], merge_result=fixture_merge_result)` where both verdicts carry `category == "schema"` and both survive dedup (non-identical `summary` strings) returns a `StructuredDisagreementResult` whose `conflict_pairs` contains a `ConflictPair(expert_a=<lower lex slug>, expert_b=<higher lex slug>, category="schema")`, AND `severity_escalation_events` is asserted as a specific integer against the fixture (covering both the zero and non-zero cases via two fixture variants).
- AC-003 [Schema validator distinguishes parse/compile errors from payload validation failures and performs no I/O side effects] — verified by T-103, which MUST assert: (a) a fixture where the skill's `SKILL.md` contains no `## Required Output Schema` fenced block causes the validator to raise `SchemaValidationError` with `kind == "schema-block-missing"` and a non-empty `detail` field — the call does NOT return a `ValidationFailure`; (b) a fixture where the skill's `SKILL.md` contains a valid schema but the payload dict is missing a required field causes the validator to return `ValidationFailure` with a non-empty `field_path` and `error_message` — the call does NOT raise; (c) a fixture where the payload satisfies the schema causes the validator to return `ValidationSuccess` — the call does NOT raise; (d) across all three fixture cases, no write is made to stdout, stderr, or any file — asserted by patching `builtins.open` in write mode, `sys.stdout.write`, and `sys.stderr.write` to assert they are never called. The parent AC-003 assertion about "structured stdout log with `decision_summary: schema-validation-failed`" is #361.2 scope (the caller emits the log after receiving `ValidationFailure`); this module asserts absence of any stdout write, not presence of a caller-side log line.
- AC-004 [Predicate registry evaluates fixture predicates correctly and MatrixRow.predicate "none" parses to Python None] — verified by T-104, which MUST assert: (a) a freshly constructed `PredicateRegistry` with `evaluate("always_true", WorkItemContext(changed_paths=[], has_user_facing_flow=False))` returns `True`; (b) `evaluate("always_false", WorkItemContext(...))` returns `False`; (c) `MatrixRow(predicate="none", ...)` has `predicate == None` after Pydantic v2 construction (the literal string `"none"` is coerced to Python `None` by the field validator); (d) `DispatchMatrixLoader.load(...)` invoked against a fixture matrix containing a row with `predicate="always_true"` and a registry that has `always_true` registered returns a valid dispatch table without raising; (e) `DispatchMatrixLoader.load(...)` invoked against a fixture matrix containing a row with `predicate="unregistered_sentinel"` and a registry that does NOT have `unregistered_sentinel` registered raises `DispatchMatrixError` at load time (asserted by checking the exception type is `DispatchMatrixError`, not `PredicateRegistryError` — the loader wraps registry misses as matrix errors to give the caller a single error type for startup validation).

## Informative Notes (Non-Normative)
- Context: This child (`#361.1`) is the pure-Python core of the orchestrator service (`#361`, Child B of `#333`). It is deliberately zero-I/O so that every component can be unit-tested without mocks or stubs of infrastructure. The C7 emission path for rejected skill outputs (FR-004 in parent spec) belongs to `#361.2` — this child's schema validator returns a typed `ValidationFailure`; the caller (#361.2) decides whether and how to emit a C7 rejected event. The dependency direction is `#361.5 → #361.1`, not the reverse: this child authors only fixture predicates; the first real predicate (`ui-fidelity-or-a11y`) is authored in `#361.5` which calls `registry.register(...)` before passing the registry to the loader.
- Tradeoffs: The zero-I/O constraint on this child maximises unit-test coverage speed and eliminates the need for any infrastructure stub at the domain/application layer. The cost is that the caller (#361.2) must wire observability. This mirrors Clean Architecture's dependency rule: inner layers know nothing about outer layers.
- Clarifications: All four open questions from the parent spec (Q-1 through Q-4) are resolved and do not generate open questions for this child. The predicate evaluation surface (Q-3, resolved as Option A OR-form) is implemented here only at the registry-mechanism level; the two consumer-extensible regex sets (`predicates.frontend.pathRegex`, `predicates.accessibility.pathRegex`) belong to the config-map in `#361.4` and the actual `ui-fidelity-or-a11y` callable in `#361.5`.
